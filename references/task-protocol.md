# 任务产出协议

需要产出文件的任务必须先读本文件。纯问答任务只在对话中回答，不适用本文件。

## 何时产出文件

用户有明确规定时以用户规定为准。没有明确规定时：纯问答任务不产出文件；检索、引用分析、综述、作者/机构分析、批量元数据、BibTeX/RIS 导出、OA 判定、PDF 清单等复杂任务产出文件。

## 任务目录

需要产出文件的任务，必须在任何 API、网页、CDP、子 Agent 或依赖检查**之前**建立集中任务目录：

- 用户已规定路径或项目已有路径规约时，按既有规定建立。
- 否则使用 `<workspace>/_academic-search/<task-id>/`。

`<task-id>` 应能反映任务内容且不重名。任务目录之外不得存放本次任务的产物；不得写入系统临时目录或 `<workspace>` 顶层。

## 主产物

| 文件 | 内容 |
|---|---|
| `protocol.md` | 原始需求、任务类型、范围与排除项、成功标准、预定来源、检索/分析方法、字段和预期交付物。调整检索式、平台或范围时，追加变更记录，不覆盖历史条目。 |
| `report.md` | 最终结果、方法、来源与时间、统计、局限及未完成项。 |
| `trace.md` | 按执行顺序的完整审计与复现轨迹，格式见下。 |
| `manifest.json` | 任务目录内所有产物清单：路径、用途、生成时间，以及必要的记录统计。 |

## trace.md

使用 Markdown 表格，按执行顺序逐行记录：

| 时间 | 平台 | query / URL | 动作 | 命中数 | 结果 | 失败信号及回退 |
|---|---|---|---|---|---|---|

失败、重试、平台切换和回退同样必须记录，不能只记成功路径。引用数、命中数和关键状态变化也写入本文件，保留来源平台与观测时间。

**禁止记录**：API Key、Cookie、Authorization 头、用户身份信息，以及含令牌或密钥的 URL。必要时脱敏后再写。

## 中间产物

检索、筛选、去重、引用分析、OA 判定和下载等关键阶段的中间结果必须及时保存，并**分类存放**：按任务自定标准（阶段、来源平台、论文批次等）归入任务目录内的不同子目录或文件，彼此可区分、便于追溯。分类标准、具体文件名与层级不作强制约定，但不得散落在任务目录之外。

所有关键阶段的中间结果都必须在 `manifest.json` 中登记。

## 子 Agent 交接

主 Agent 给子 Agent 的提示词必须给出本次任务目录路径，并规定：所有中间产物（工具脚本、检索结果、筛选结果、抓取结果等）保存在该任务目录内的独立路径，不得写到任务目录之外，也不得写入系统临时目录或 `<workspace>` 顶层。子 Agent 完成后须回报其产物的相对路径，由主 Agent 登记到 `manifest.json` 并纳入最终报告。

## 完成判定

需要产出的任务只有在任务目录包含 `protocol.md`、`report.md`、`trace.md` 和 `manifest.json`，且关键中间结果已保存并登记后，才可报告完成。纯问答任务不适用此文件要求。
